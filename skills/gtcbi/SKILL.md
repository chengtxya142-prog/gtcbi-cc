# Global Trade Customer Background Investigation V2.0.1

Read [operating rules](references/rules.md) before research. For delivery, read [output contract](references/output-contract.md). Use existing authorized browsing and connectors; do not assume a particular provider exists.

1. Reuse confirmed seller/product/market/customer/cooperation configuration. Resolve missing decision-critical inputs and confirm new keywords or material changes.
2. Declare entity, country, scope, mode, required deliverables and source restrictions. Read existing records before researching.
3. Verify the entity before identity-dependent personnel work. Research business, procurement and timing; then choose a route based on evidence and gaps.
4. Match research depth to purpose. Preserve existing useful evidence. Budget exhaustion does not fulfill a required deliverable.
5. Compare buyer conditions with seller capabilities. Separate facts, hypotheses, unknowns and conflicts. Report which action each gap affects.
6. Independently report execution, deliverables, draft readiness, cooperation conditions and handoff. Default to no numerical score.
7. Refresh only affected facts when new evidence arrives; preserve historical dates and judgments.
8. Produce the requested output. Draft outreach only when requested; actual sending requires explicit authorization. A draft never proves contact occurred.

Do not transfer a source workflow's module number, fixed headcount, query quota or unapproved scoring policy into this generic model. Apply configured source exclusions before source selection. Read-only authorization does not authorize outreach or CRM writes.

Use the repository's optional offline checker for a structured JSON run. Passing it does not verify the truth or adequacy of the evidence; perform semantic review as described in the output contract.
