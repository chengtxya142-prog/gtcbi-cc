## 1. 目的与范围

在现有 V2.0.1 研究流程之前增加“画像确认 → 关键词确认 → 行业客户发现 → 人工选择及最终确认”的执行入口。仅对操作人批准的客户执行完整背调。

这是对原项目的增量设计，不是恢复旧 V2.0 临时仓库，也不是重新创建一个独立模型。当前仓库已声明版本 2.0.1，本轮沿用该版本，不移动已有版本标签、不修改历史发布。文档日期不等于客户研究日期。

本轮不建设独立网站、CRM、自动外联或常驻爬虫。Skill 依赖宿主现有搜索、读取、交互及文件能力；没有对应能力时如实报告限制。

## 2. 总体流程

1. 检查相关搜索、读取和保存能力；这一步不开展客户研究。
2. 预填可读取的操作人默认公司行业及主要产品。
3. 操作人确认或修改；补齐目标市场、客户类型、合作目标等本次必要配置。
4. 保存独立的本次画像快照，不覆盖默认画像。
5. 生成推荐关键词，允许操作人自由新增、修改、删除或完全替换。
6. 确认本次关键词包，保存配置版本及实际确认依据。
7. 根据关键词发现候选客户；首批默认展示 10 家。
8. 展示候选池，所有客户的选框初始为空。
9. 操作人选择客户，并明确“确认选中客户并开始背调”。
10. 为每个批准客户建立独立运行记录，接入现有完整研究流程。

候选发现、客户选择、正式研究是不同阶段；关键词确认只允许候选发现，不自动授权对搜索结果开展完整背调。

## 3. 操作人画像及关键词

### 3.1 默认画像和运行画像

- 行业和产品描述的是本次作为供应方/合作提出方的公司，不是候选客户的行业。
- 默认可使用操作人所属公司的资料，也可以临时切换其他公司、行业或产品。
- 只有确实可读取且来源明确的默认资料可以预填；没有默认资料时向操作人收集，不凭空生成。
- 默认画像与本次运行快照分别保存。修改本次配置不覆盖默认画像；覆盖默认值需要单独明确请求。
- 不在通用 Skill 或公开仓库中硬编码任何用户公司的私有资料。
- “保存”须区分当前对话记录和持久化文件；没有保存能力时不得声称已永久保存。

### 3.2 开放关键词包

系统推荐仅是辅助，不是封闭词库。支持产品词、同义词、渠道词、场景词、职位词、竞品词、当地语言词和排除词；不强制每组都必须有内容。

操作人可接受推荐、混合自定义词或完全替换。保存最终生效词、推荐/自定义来源和必要的变更记录。不得偷偷恢复已删除词，不得因为不在行业词库中就拒绝自定义词。

关键词确认在搜索候选客户之前。用户须明确确认最终词包；笼统的“继续”不能用来虚构对未展示词包的批准。

公司、行业、产品、市场或关键词含义发生实质变化时，生成新配置修订并重新确认。旧候选和旧研究保留其原快照；不得静默套用新配置或转移旧批准。

## 4. 候选发现和批次数量

采用“验证型候选发现”：查看官网或可靠来源，核对基本公司线索及其与本次配置的初步关联。搜索摘要只是线索，不能假装已经阅读来源。

首批默认目标为 10 家。后续点击或请求“继续查找”时，必须由操作人填写本次所需数量；不默认继续按 10 家执行。后续数量必须为正整数；缺失或无效时只询问数量，不启动新批次。

数量是候选结果目标，不是固定搜索次数。记录本次请求数量、实际获得数量、实际检索范围和停止原因。来源不足、权限受限或预算耗尽时返回实际数量和缘由，不凑数、不编造，也不将大批数量视为无限搜索授权。

候选发现可以核对名称、国家、官网和业务相关性，但不完成正式 F1–F6、不授予商业等级、不推断采购预算或合作意向。

### 4.1 候选展示格式

每个客户展示且仅以以下五项作为默认业务信息：

- [ ] CAND-001｜公司名
  - 国家：
  - 官网：
  - 匹配理由：
  - 发现来源：

以上是空白格式，不是真实客户记录。发现来源使用实际查看的直接来源链接；匹配理由注明其初步线索性质。无法确认的字段标为未核验，不以猜测填充官网或国家。

候选 ID 在本次任务中稳定、跨批次连续，不因排序改变而重新分配。批次编号、日期和状态作为记录元数据，不强迫在每张卡中重复展示。

### 4.2 候选池操作

- 选择一个或多个客户。
- 确认选中客户并开始背调。
- 继续查找更多客户，并填写本次数量。
- 停止查找，保留当前候选池。
- 手动添加客户；手动添加不等于批准背调。
- 导出候选名单；导出不等于批准背调。

### 4.3 去重

后续批次排除已展示、已选择及已明确排除的同一客户。记录公司规范名、国家、官网规范化域名及已知别名，避免 URL 参数、协议或 www 差异造成重复。

共享集团域名是待核对的重复信号，不足以证明不同国家子公司是同一法律实体。以公司/实体范围核对；不得仅凭共享域名错误合并不同客户，也不得将重复实体包装成新候选。

## 5. 人工执行门

必须同时满足：

1. 本次画像已确认。
2. 本次关键词包已确认。
3. 操作人明确选择至少一个有效候选 ID。
4. 操作人明确确认对该选择集合开始背调。

保存被批准的候选 ID 集合、配置修订、实际确认依据和可获取的确认时间；不得伪造时间或用户原话。

所有选框默认未选中。勾选本身不启动研究。仅查看名单、继续查找、改关键词、加入候选池、导出名单及沉默均不算通过执行门。

确认只适用于当时的客户集合；后来新增候选不自动继承批准。重复提交同一确认不得重复创建客户任务。

### 5.1 交互能力降级

宿主确实支持并能回传多选状态时，使用空白可多选控件及最终确认动作。

不支持时，显示 Markdown 空白选框和稳定候选 ID，由操作人明确回复，例如“选择 CAND-001、CAND-003，确认开始背调”。一句话可同时表达选择和最终确认。不得将静态 Markdown 声称为实际可点击按钮，也不得猜测用户在界面上勾选了什么。

用户已指定客户时，无需为了流程形式再搜索 10 家：将指定客户作为手动候选，完成必要配置与同一明确选择/确认记录后执行。导出已有报告不新增研究授权，也不强迫重新发现客户。

## 6. 数据记录与状态

### 6.1 数据所有权

| 记录 | 内容与边界 |
| --- | --- |
| 默认画像 | 可用的默认行业、产品等；不能被临时配置覆盖 |
| 发现任务快照 | 本次公司、行业、产品、市场、客户类型、合作目标、限制、关键词和确认版本 |
| 候选批次 | 批次 ID、请求/实际数量、配置版本、实际检索日期及不足原因 |
| 候选客户 | 稳定 ID、五项展示信息、来源、实体去重键及待选/已选/已排除状态 |
| 执行批准 | 选中 ID 集合、配置版本、实际确认依据；不代表外联授权 |
| 客户研究记录 | 每客户独立运行 ID、快照引用、证据、F1–F6、缺口、决策、研究与交付状态 |
| 历史 | 配置修订、批次及先前结论保留；不能以新研究日期覆盖历史日期 |

以上为逻辑记录，可由宿主支持的对话或授权文件承载，不强制数据库。发现任务 ID 与单客户运行 ID 不得混用。

### 6.2 状态分离

操作人看到的流程为：画像待确认 → 关键词待确认 → 候选发现中 → 候选待选择 → 目标已确认/可以开始背调 → 背调执行中 → 完成、部分完成或阻塞。

这些是入口进度标签，不替代原有研究执行、必需交付、草稿就绪、合作条件、实际交接和每格式导出状态。选择客户不等于研究完成；完成研究不等于取得全部要求的联系人，也不等于发生了外联。

多客户任务分别记录状态，单客户错误不覆盖整个批次结果。

## 7. 通过执行门后的完整 Workflow

使用当前仓库 skills/gtcbi/references/rules.md 中按职责映射的流程；不依据旧编号机械复制 Workflow 4.7.1，也不恢复旧行业固定人数门槛、评分权重或查询配额。

执行次序：

1. 建立客户独立运行记录，固定获准的画像、关键词、范围和交付物。
2. 复核工具及来源能力，读取已有适用记录。
3. F1：客户主体、品牌/集团/法律实体和官网归属核验。
4. F2–F4：业务渠道、采购/需求/时机、公司入口与相关人员核验。
5. F5：风险、准入分流、重要缺口及动作限制。
6. 根据证据进行必要的定向或全面深挖，完成 F6 双向可行性与下一步。
7. 综合最终商业判断和内容质量检查，分别报告研究和交付状态。
8. 按请求生成报告及导出；可选邮件模块只生成草稿。

F1–F6 是稳定职责，不代表每个模块只能访问一次。新证据可要求回到受影响模块及最终决策。

候选线索必须在正式研究中评价其支持力、实体范围和时效；适用且已查看的来源可以复用，不强制重复打开每个页面。候选匹配理由不能自动升级成正式结论。

输出保留：是否跟进、理由、最强反对证据或不确定项、合作切入点、当前下一步，以及继续/暂缓/停止条件。没有实际证据不能标成已发送、已回复或已安排会议。

## 8. 异常和暂停

### 8.1 F1 主体冲突

该客户暂停正式背调，在用户界面明确标注“主体冲突”，原因码为 identity_conflict。实现时映射到现有状态结构，不制造另一套相互矛盾的完成状态。

必须同时记录：

- 具体缘由，如同名公司、官网与注册主体不一致、国家不一致或品牌与法律实体关系不明。
- 冲突双方的主张、来源、实体范围及已知日期。
- 被阻塞的结论和后续步骤。
- 操作人需要补充/确认的信息，以及解除暂停的条件。

保留已获得的证据；暂停期间不继续该客户正式深挖，不把冲突解释为低信誉。收到澄清后先复核主体，满足条件才恢复。其他已批准客户正常推进。

### 8.2 其他失败

- 来源不可访问：记录具体来源、原因和未核验项，可继续其他授权且适用的来源；不绕过访问控制。
- 某客户失败：只更新该客户状态，其余已批准客户继续。
- 用户中止：停止尚未开始的剩余任务，保留已有结果和实际中止范围。
- 工具或保存失败：报告失败环节；不假装已经执行、永久保存或导出。
- 主体冲突不是唯一停止原因；其他已证实的重要阻碍仍遵循当前规则。

## 11. 审核、合并和清理

在 feat/v2.0.1-discovery-gate 上保存设计，完成用户整体审核后再编写实施计划。修改与测试继续在该分支进行，不提前覆盖 main。

实施完成后展示变更、验证结果及已知限制；用户确认后合并到 main，验证主分支，再删除临时分支。不强制推送、不自动删除未合并的修改。

删除已合并分支不会删除主分支内容或提交历史。设计文档默认保留供排查；删除设计文档属于单独操作，不随分支清理自动执行。

## 12. 设计自检

- 范围：仅增加可配置发现和人工执行门，保留现有研究与输出职责。
- 一致性：关键词确认在发现前；选择加最终确认在正式研究前。
- 状态：候选、执行批准、研究、交付、外联分离；主体冲突有具体缘由。
- 数量：首批默认 10，后续每次填写；不足如实说明。
- 交互：区分真实多选控件和静态选框，文字确认可明确表达授权集合。
- 隐私：公开仓库只存规则与合成测试，不保存操作人私有默认画像或真实客户数据。
- 实施状态：这是一份设计，不声称代码、UI、搜索或导出已实现。
